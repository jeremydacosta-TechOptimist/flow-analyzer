# Example flow exports

These files are deterministic synthetic exports generated by the tool itself.
They contain no real traffic, no personal data and no secrets: addresses come
from the documentation ranges (`192.0.2.0/24`, `198.51.100.0/24`,
`203.0.113.0/24` and `2001:db8::/32`).

| File | Format | Records | Size | Notes |
| --- | --- | ---: | ---: | --- |
| `flows-v5.bin` | NetFlow v5 | 12 | 600 B | header sampling interval 1, engine type/id 0, all records IPv4 |
| `flows-v9.bin` | NetFlow v9 | 12 | 776 B | IPv4 and IPv6 templates plus an options template carrying the sampling interval; source ID 7 |
| `flows-ipfix.bin` | IPFIX v10 | 12 | 864 B | template set, options template set and data sets; observation domain 99 |

The traffic models a small lab: HTTP/HTTPS, DNS, SMTP, SSH and NTP traffic to
servers in `198.51.100.0/24`, a remote HTTPS client to `203.0.113.0/24`, ICMP
echo traffic, and IPv6 HTTPS/DNS flows under `2001:db8::/32`. Every fourth flow
is the reverse direction of the previous one, so bidirectional conversations are
present in the fixtures.

All three files decode to the same twelve flows (the same seed is used for each
format), which makes them useful for comparing the formats:

```powershell
flowanalyzer decode examples/flows-v9.bin
flowanalyzer analyze examples/flows-ipfix.bin
flowanalyzer report examples/flows-v5.bin -o report.html
```

## Regenerating the fixtures

The fixtures are committed so that tests and the README demos work offline. To
regenerate them deterministically:

```powershell
flowanalyzer generate --format v5 --out examples/flows-v5.bin
flowanalyzer generate --format v9 --out examples/flows-v9.bin
flowanalyzer generate --format ipfix --out examples/flows-ipfix.bin
```

The generator defaults are `--flows 12 --seed 7`, so repeated runs produce
byte-identical files.
